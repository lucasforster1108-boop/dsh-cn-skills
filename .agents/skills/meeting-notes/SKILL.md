# 会议纪要整理

## 输入处理

转写稿通常口语化、重复、说话人标注混乱。动笔前先做三件事：

1. **认人**：把发言与人物对应（转写稿有标注按标注；没有标注、又涉及「谁负责」时，不猜人，待办负责人写「待确认」）。
2. **分拣**：把内容分成四堆——达成的决议、仍在讨论未定的议题、明确的待办、闲聊与重复（直接丢弃）。
3. **抠要素**：每条决议抠「决定了什么」；每条待办抠「谁、做什么、什么时候之前」；三要素缺哪个标哪个。

## 输出结构

```
# 会议纪要：<主题>（<日期>）

参会：<名单，无则写「据记录整理，名单待确认」>

## 结论摘要（3 条以内，先看这里就够）
- …

## 决议事项
- 决议内容（一句一条，写清口径与范围）

## 待办清单
| 事项 | 负责人 | 期限 |
|---|---|---|

## 未决议题
- 议题 + 卡在哪 + 下一步由谁推进确认

## 待确认
- 记录里听不清、自相矛盾、需要当事人核对的点
```

小会（3 人以下、半小时内）可合并「结论摘要」与「决议事项」，不硬套全结构。

## 写作规范

- 纪要用书面语重述结论，不摘抄口语原话；数字、金额、日期、版本号逐字保留原文口径。
- 「大家觉得可以」「应该问题不大」不算决议——没有明确拍板表述的，进「未决议题」。
- 同一事项多次讨论的，只记最终结论，并注明口径变化（如「由 A 方案改为 B 方案」）。

## 红线

- **不编造决议与承诺**：没有拍板的写未决，没有点名的负责人写「待确认」，期限没提的留空不替人加码。
- 不做归因评价（谁对谁错、谁消极），纪要只记事实与结论。
- 涉及人名与公司敏感信息时按原文呈现，不外扩、不联想。
