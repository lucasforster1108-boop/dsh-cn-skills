# PPT 大纲与逐页脚本

## 工作流

1. **先定三件事**：主题与场合（汇报/路演/答辩/培训）、时长（决定页数：约 1 分钟 1 页）、对象（领导看重结论，客户看重收益，同行看重细节）。信息不全按最常见场景默认并注明。
2. **先给一页纸大纲**：全篇逻辑一句话（如「问题 → 方案 → 证据 → 计划」），再列章节与每章页数分配，用户确认结构后再展开逐页——结构不对，逐页写得再细也白搭。
3. **逐页脚本**，每页给齐五项：
   - 页码与页面标题（结论式标题：不写「项目背景」，写「市场还在以每年 20% 增长」）；
   - 本页要点 3–5 条，每条一行，是讲稿要点不是整段文章；
   - 版式/配图建议（放什么图、什么图表、数据用柱状还是折线，一句话说清）；
   - 演讲备注 2–3 句（这一页开口怎么讲、强调哪个数）；
   - 与上页的过渡一句话（可选，关键页给）。
4. **收尾页固定件**：结论页（重述 3 个核心点）、行动/请求页（要对方做什么）、致谢/答疑页。需要对方决策的汇报，请求页必须写清「希望今天定什么」。

## 红线

- 不替用户编数据：图表里的数据只用用户给的，没给的标注「此处需填真实数据」并给建议口径。
- 一页不塞两件事：发现某页要点超过 5 条或讲两个主题，主动拆页并说明。
- 标题不用空词：「赋能、抓手、闭环、生态」类词除非用户行业惯用且要求，否则换具体说法。
- 不承诺视觉效果：本技能产出内容脚本，不排版美化；交付时说清这一点。
