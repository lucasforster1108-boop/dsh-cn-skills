# 中文简历优化

## 输入

- 用户的现有简历或经历描述（必需；没有就先向用户要，别凭空写）。
- 目标岗位的 JD（有则做对齐，没有就按通用优化处理，并说明未对齐 JD）。

## 工作流

1. **先诊断再动手**：通读简历，列出三类问题——流水账（只写职责不写成果）、无量化（没有数字支撑）、与目标岗位无关的内容占比过高。诊断结论用 3–5 条在交付时一并给出。
2. **经历改写**：每段经历改成「动词 + 做了什么 + 结果/数据」的句式：
   - 动词升级：负责 → 主导/牵头/交付/上线（按真实参与程度选，不夸大层级）；
   - 结果落地：写清产出物与影响范围（服务多少用户、覆盖多少门店、周期从 X 缩到 Y）；
   - 数字优先：原文有数字的一律保留并前置；没有数字、又确实能量化的，在交付稿中标「待补充：建议补 XX 数据」，不替用户填数。
3. **JD 对齐**（有 JD 时）：提取 JD 的硬技能与关键词，逐项核对简历是否体现；用户真具备但简历没写的，提示补充到对应经历下；不具备的不写、不暗示。
4. **结构整理**：按「个人信息（一行）→ 求职意向 → 工作经历（倒序）→ 项目经历 → 技能 → 教育」排版；与岗位无关的早期经历压缩为一行或删除（删除前在诊断里说明）。
5. **交付**：先给**改后全文**（可直接复制投递），再给诊断与改动说明（不超过 8 条），最后列「待补充清单」（缺的数据、缺的信息）。

## 红线

- **不编造、不夸大**：没做过的项目、没拿到的证书、不会的技能一律不写；职级、公司、时间等硬事实与原文一字不改，发现自相矛盾的时间线要提示用户。
- 不写自我评价式空话（「吃苦耐劳、沟通能力强」），用经历条目自己说话。
- 不替用户承诺入职时间、薪资期望等求职意向内容，原文没有就留空。
