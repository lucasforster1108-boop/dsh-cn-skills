# 周报生成

## 输入处理

用户的材料通常是流水账：干了什么、开了什么会、帮谁处理了什么。先在心里做三件事再动笔：

1. **归类**：把零散条目按项目/主题合并（同一件事的多次跟进合并为一条，写出进展而不是次数）。
2. **提炼结果**：每条工作写「做了什么 → 产出/结果是什么」，只写动作不写结果的条目尽量从上下文补出结果；补不出的标「待补充」。
3. **识别风险与阻塞**：延期、等他人、缺资源、需求变更，单独成节，不埋在完成事项里。

## 输出结构

```
# 周报（X月X日–X月X日）

## 本周完成
- 事项一句话 + 结果/数据（动词开头，量化优先）
- …

## 进行中
- 事项 + 当前进度（百分比或阶段）+ 预计完成时间

## 问题与风险
- 问题 + 影响 + 需要的协助/决策

## 下周计划
- 事项 + 预期产出
```

篇幅按用户材料量伸缩：材料少时合并「进行中」进完成节，不硬凑四节；日报只保留完成与计划两节；月报在四节前加一段「本月小结」（3–5 句，只写最重要的成果与教训）。

## 写作规范

- 每条一句话，动词开头：完成、上线、交付、推进、协调、修复——不用「进行了」「开展了」这类空动词起头。
- 有数字必写数字（完成量、覆盖人数、节省时间、错误率变化）；没有数字的条目不编数字。
- 人名只在「需要协助」时出现，周报不是表扬信也不是甩锅书。
- 不写正确的废话：「积极推进各项工作」「取得良好成效」这类句子出现即删。

## 红线

- **不编造**：材料里没有的成果、数据、进度一律不写；推断的进度标「（据材料推断，请确认）」。
- 不替用户表态承诺下周交付时间，材料没写的预计时间留空待填。
